# 4.6: Customizing `tailwind.config.js`

**Difficulty:** Intermediate+
**Module:** [Module 4: Tailwind CSS](../README.md)

## What You'll Learn
- Why real projects run Tailwind through a local build tool instead of the Play CDN
- The four files a minimal Tailwind CLI project needs: `package.json`,
  `tailwind.config.js`, an input CSS file, and an HTML file
- How to add custom colors, font sizes, and spacing values under `theme.extend`
- How the `content` array tells Tailwind which files to scan for class names
- How to run `npm install` and `npm run build` and read the generated output file

## Prerequisites
Topics 4.1-4.5. You do not need prior experience with npm or build tools &mdash; this
topic explains every command from scratch.

## Explanation

Up to now, every demo has loaded Tailwind straight from the **Play CDN**:

```html
<script src="https://cdn.tailwindcss.com"></script>
```

This is great for quick experiments, but it ships every single Tailwind utility class to
the browser and compiles them on the fly with JavaScript, which is far too slow and heavy
for a real, deployed website. In an actual project you install Tailwind as a **build
tool**: it scans your HTML/JS files for the class names you actually used, and generates
one small CSS file containing only those classes. This topic sets that up for the first
time.

A minimal Tailwind CLI project has four pieces:

- **`package.json`** &mdash; lists `tailwindcss` as a `devDependency` (a tool only needed
  during development, not something the browser downloads) and defines npm **scripts**,
  which are just named shortcuts for terminal commands. This project defines `build`
  (compile once) and `dev` (compile, then keep watching for changes).
- **`tailwind.config.js`** &mdash; Tailwind's configuration file. The `content` array tells
  it which files to scan for class names (`./index.html` here), and `theme.extend` is
  where you add your *own* design tokens on top of Tailwind's defaults, without replacing
  them.
- **`input.css`** &mdash; a tiny source stylesheet containing three special directives,
  `@tailwind base;`, `@tailwind components;`, and `@tailwind utilities;`, which the build
  tool expands into real CSS.
- **`index.html`** &mdash; ordinary HTML that links to the *compiled* stylesheet
  (`dist/output.css`), not to `input.css` and not to any CDN script.

The important part of `tailwind.config.js` for this topic is `theme.extend`:

```js
theme: {
  extend: {
    colors: { brand: '#6d28d9' },
    fontSize: { huge: '3.5rem' },
    spacing: { 18: '4.5rem' },
  },
},
```

This adds a new color (usable as `bg-brand`, `text-brand`, `border-brand`, etc.), a new
font size (`text-huge`), and a new spacing value (usable in padding/margin/gap utilities
like `p-18`), all alongside the hundreds of utilities Tailwind already ships with. Using
`extend` (instead of replacing `theme` directly) keeps every default utility working while
adding your own on top.

## The Demo

This folder is a complete, self-contained Tailwind project:

- `tailwind.config.js` defines the `brand` color, the `huge` font size, and the `18`
  spacing value described above.
- `input.css` has the three `@tailwind` directives.
- `index.html` links `dist/output.css` (generated by the build, not written by hand) and
  uses both custom utilities (`text-huge`, `text-brand`, `bg-brand`, `p-18`) and ordinary
  built-in ones (`rounded-lg`, `border`, `font-semibold`) side by side, so you can see that
  customizing the config does not take anything away.

`dist/output.css` does not exist yet in a fresh checkout &mdash; it's generated by running
the build, exactly like it would be in a real project (compiled output is normally not
something you hand-write or commit before building).

## How to Run

From inside this folder (`04-tailwind-css/06-customizing-tailwind-config/`):

1. `npm install` &mdash; downloads Tailwind (and its dependencies) into a local
   `node_modules` folder, based on `package.json`.
2. `npm run build` &mdash; runs the `build` script from `package.json`, which invokes the
   Tailwind CLI to read `input.css`, apply `tailwind.config.js`, scan `index.html` for
   class names, and write the final CSS to `dist/output.css`.
3. Open `index.html` in your browser.

If you want the build to automatically re-run every time you edit a file, use `npm run
dev` instead of `npm run build` &mdash; it watches for changes and keeps `dist/output.css`
up to date.

## Try It Yourself

Add a second custom color to `tailwind.config.js`, for example `accent: '#059669'`, under
`theme.extend.colors`. Re-run `npm run build`, then add a `bg-accent` class to a new
element in `index.html` and reload the page to confirm your new color compiled correctly.

## Key Takeaways
- The Play CDN is fine for quick demos, but real projects compile Tailwind locally so only
  the classes you actually use end up in the shipped CSS.
- A Tailwind CLI project needs `package.json`, `tailwind.config.js`, an input CSS file
  with the three `@tailwind` directives, and your HTML/JS files.
- `content` tells Tailwind which files to scan for class names in use.
- `theme.extend` adds your own colors, font sizes, and spacing on top of Tailwind's
  defaults without removing anything.
- `npm run build` compiles once; `npm run dev` recompiles automatically as you edit files.
