# 3.5: Customizing the Theme

**Difficulty:** Intermediate
**Module:** [Module 3: Bootstrap](../README.md)

## What You'll Learn
- Why customizing Bootstrap's actual design tokens requires a real Sass build, not a CDN
- How Bootstrap's Sass source is organized around variables with default values
- How to override those variables before importing Bootstrap's Sass
- How to run a local build step with npm and the `sass` compiler
- How to verify a customized build actually changed the compiled CSS

## Prerequisites
Module 1: HTML, Module 2: CSS, Topics 3.1-3.4

## Explanation
Every other topic in this module loads Bootstrap's already-compiled CSS from a CDN. That
file is fixed — you cannot change what color `$primary` maps to, or how rounded corners
are by default, because the CSS has already been generated from Bootstrap's Sass source
with Bootstrap's own default values baked in.

Bootstrap is actually written in **Sass** (`.scss` files), a superset of CSS that supports
variables, and every color, size, and spacing value used throughout Bootstrap's components
is driven by a Sass variable with a default, for example:

```scss
$primary:       #0d6efd !default;
$border-radius: 0.375rem !default;
```

The `!default` flag means "use this value only if it hasn't already been set." That is the
mechanism this topic relies on: if your own Sass file sets `$primary` to a different value
*before* Bootstrap's Sass runs, Bootstrap sees your value already set and skips its own
default — so every single component that uses `$primary` (buttons, alerts, links, form
focus rings, and more) picks up your color automatically, with no per-component overrides.

This is why customizing the theme needs a **local build**: something has to run the Sass
compiler on your source file to produce the final CSS. This folder sets that up with:

- `package.json` — lists `bootstrap` and `sass` as `devDependencies` (installed locally
  into `node_modules`, not loaded from a CDN), and defines a `build` npm script that runs
  the Sass compiler.
- `custom.scss` — first sets overridden variables (`$primary`, `$border-radius`,
  `$font-family-sans-serif`), then imports Bootstrap's full Sass source with
  `@import "bootstrap/scss/bootstrap";`. The order matters: the overrides must come first.
- `dist/custom.css` — the compiled output, generated by running the build script. This file
  is what `index.html` actually links, instead of the CDN.

Because `bootstrap` is installed as an npm package here, `custom.scss` can import
`"bootstrap/scss/bootstrap"` and the Sass compiler resolves it from `node_modules`.

## The Demo
`index.html` links `dist/custom.css` and uses completely ordinary Bootstrap classes —
`btn btn-primary`, `card`, `alert alert-primary` — the exact same classes used in Topic
3.3. Nothing in the HTML says "make this purple" or "round this corner more." The visual
difference (a purple primary color instead of Bootstrap's default blue, and noticeably
larger rounded corners) comes entirely from the Sass variable overrides compiled into
`dist/custom.css`, proving that a themed Bootstrap build changes component appearance
globally without touching a single HTML class.

## How to Run
This is the one topic in this module that needs Node.js and a build step instead of just a
browser:

1. Open a terminal in this folder (`03-bootstrap/05-customizing-theme`).
2. Run `npm install` to download `bootstrap` and `sass` into a local `node_modules` folder.
3. Run `npm run build` to compile `custom.scss` into `dist/custom.css`.
4. Open `index.html` directly in your browser.

If you change a variable in `custom.scss`, re-run `npm run build` and refresh the browser
to see the update — the build step does not watch files automatically.

## Try It Yourself
Open `custom.scss` and change `$primary` to a different hex color of your choice (or add
`$secondary: #your-color;`). Re-run `npm run build`, refresh `index.html`, and confirm the
buttons and alert picked up the new color without any HTML changes.

## Key Takeaways
- Bootstrap's CSS is generated from Sass variables marked `!default`, which only apply if
  nothing set that variable first.
- Setting your own variable value before `@import "bootstrap/scss/bootstrap";` overrides
  Bootstrap's default everywhere that variable is used.
- Customizing real design tokens (not just adding utility classes) requires compiling
  Bootstrap yourself with a tool like `sass`, rather than using the CDN build.
- `npm install` downloads the packages listed in `package.json`; `npm run build` runs the
  script that compiles Sass to CSS.
- A themed build changes component appearance globally while the HTML and class names stay
  completely unchanged.
