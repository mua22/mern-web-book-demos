Why Semantic HTML Matters

Published September 6, 2026 by Usman Akram

When you're new to HTML, it's tempting to build every page out of nothing but <div> tags: a "div" for the header, a "div" for the navigation, a "div" for the main content, and so on. This is sometimes called div-soup: a page that works visually but tells a screen reader, a search engine, or another developer nothing about what each part of the page actually is.

Screen Readers

A screen reader is software that reads a page aloud for users who are blind or have low vision. It relies on semantic tags to let users jump straight to the navigation, skip to the main content, or understand that a block of text is a self-contained article. A page built only from <div>s gives the screen reader no such structure to announce.

SEO

Search engines also read the structure of a page, not just its words. Tags like <main>, <article>, and <nav> give a search engine strong hints about which content is the actual page content and which is just navigation or supplementary, which affects how (and whether) your page is ranked.

Maintainability

Semantic tags also help the next developer, which is often you, six months later. A tag named <footer> is immediately understandable; a tag named <div class="bottom-box-3"> is not.

A Short Note on Color Contrast

Accessibility isn't only about tags: text also needs enough contrast against its background to be readable, especially for users with low vision or color blindness. Light gray text on a white background might look "clean" but can be very hard to read. As a rule of thumb, aim for dark text on a light background (or the reverse) rather than two similar, low-contrast shades.

Quick Tip

You can still use <div> and <span>; they are not "wrong". Use them for generic grouping when no semantic tag fits, and reach for a semantic tag whenever one does.
